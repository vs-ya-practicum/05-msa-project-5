# Краткий анализ технологических решений

Сравнение выполнено для ежедневной выгрузки 5 000–10 000 строк в CSV без дополнительной логики обработки данных. Согласно согласованной As-Is-диаграмме, данные из выделенных БД микросервисов сначала объединяются и сохраняются в промежуточной «БД прайс-листов» PostgreSQL, затем экспортируются в CSV. Kubernetes уже используется в инфраструктуре магазина. Знак **+** обозначает преимущество, **−** — ограничение применительно к этой задаче.

## Вывод

Рекомендуемое решение — **Kubernetes CronJob с небольшим приложением для объединения данных и выгрузки** в существующем кластере. CronJob ежедневно в 06:00 создаёт Job и Pod, в котором приложение выполняет цепочку: чтение БД микросервисов → объединение данных → сохранение в БД прайс-листов → экспорт CSV. Экспорт начинается после успешного завершения объединения и сохранения данных. Для этого короткого последовательного процесса отдельная платформа Airflow, конфигурация Spring Batch и распределённые вычисления Spark не дают достаточных преимуществ, чтобы оправдать дополнительную сложность.
